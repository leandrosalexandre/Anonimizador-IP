# Decisões técnicas

Registro das decisões tomadas durante a implementação, por fase. A fonte de verdade continua sendo o

## Fase 0 — Estrutura e PWA offline

| Tema           | Decisão                                                                                                                                                                                                                                                                                                       | Motivo                                                                                                                                                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Versões        | Vite 8, React 19, TypeScript 6.0, vite-plugin-pwa 2, Vitest 5, Playwright 1.63, ESLint 10                                                                                                                                                                                                                     | Versões estáveis atuais. TypeScript fixado em 6.0 (não 7) porque o typescript-eslint ainda não suporta o 7.                                                                                                                              |
| Roteamento     | `HashRouter` (React Router 7)                                                                                                                                                                                                                                                                                 | O GitHub Pages não tem fallback de SPA; com hash, qualquer rota abre offline a partir do `index.html` pré-cacheado.                                                                                                                      |
| CSP            | Meta tag injetada **só no build**, logo após o `charset`: `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self'; img-src 'self' blob: data:; font-src 'self'; connect-src 'self'; worker-src 'self' blob:; manifest-src 'self'; object-src 'none'; base-uri 'self'; form-action 'none'` | O `wasm-unsafe-eval` já entra porque o Tesseract (Fase 3) exige. O servidor de desenvolvimento precisa de scripts inline e websocket (HMR); a CSP vale no `preview`, nos E2E e em produção. `frame-ancestors` não funciona via meta tag. |
| Service worker | `registerType: 'prompt'`, `clientsClaim: true`, sem `skipWaiting`                                                                                                                                                                                                                                             | Na primeira instalação o app já fica pronto para offline; atualizações só com confirmação do usuário.                                                                                                                                    |
| Pré-cache      | Todos os `js, css, html, svg, png, webmanifest, json, wasm, traineddata`; limite de 40 MB por arquivo; sem cache em tempo de execução                                                                                                                                                                         | Já preparado para o WASM e o `por.traineddata` da Fase 3.                                                                                                                                                                                |
| Registro do SW | `injectRegister: null` + hook `useRegisterSW`                                                                                                                                                                                                                                                                 | Evita script inline, incompatível com a CSP.                                                                                                                                                                                             |
| UI             | CSS próprio com variáveis, fonte do sistema, tema claro/escuro por `prefers-color-scheme`, alvos ≥ 44 px                                                                                                                                                                                                      | Sem fontes nem bibliotecas externas; pacote pequeno.                                                                                                                                                                                     |
| Logs           | Regra ESLint `no-console` permite só `info`, `warn` e `error`                                                                                                                                                                                                                                                 | Reforça o requisito 2.6 (sem logs de conteúdo); revisão continua necessária.                                                                                                                                                             |
| Ícones         | Gerados de `public/favicon.svg` por `npm run icons` (Chromium do Playwright) e versionados                                                                                                                                                                                                                    | Build não depende de ferramenta externa. Inclui ícone _maskable_ para o Android.                                                                                                                                                         |
| Lighthouse     | A categoria "PWA" foi removida do Lighthouse (v12). O aceite equivalente é coberto por E2E: `Page.getInstallabilityErrors` do Chrome vazio, SW controlando a página e app abrindo offline. Lighthouse 12 roda nas demais categorias.                                                                          | Resultado na Fase 0: desempenho 98, acessibilidade 100, boas práticas 100, SEO 100.                                                                                                                                                      |
| CI/Pages       | Um workflow: lint + unitários + E2E em todo push; publicação só a partir da `main`                                                                                                                                                                                                                            | Nada é publicado sem os testes passarem.                                                                                                                                                                                                 |
| Auditoria npm  | 4 alertas de severidade baixa (`deepmerge` em `workbox-build`)                                                                                                                                                                                                                                                | Dependência apenas de build, não vai para o app; a única "correção" proposta rebaixa o vite-plugin-pwa para 0.2.                                                                                                                         |

## Fase 1 — Cofre criptografado

| Tema                     | Decisão                                                                                                                                                                                                                          | Motivo                                                                                                                                                                         |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Nomes dos campos         | Código e arquivo `.ipcofre` usam nomes em inglês (`name`, `createdAt`, `updatedAt`, `kdf.salt`, `kdf.iterations`, `payload`), equivalentes a `nome`, `criadoEm`, `atualizadoEm`, `salt`, `iteracoes`, `payloadCifrado` do SPEC 4 | Regra do SPEC: código em inglês.                                                                                                                                               |
| Cifra                    | AES-GCM 256, IV aleatório de 12 bytes a cada gravação; chave PBKDF2-SHA-256 com 600.000 iterações e salt aleatório de 16 bytes por cofre; chave não exportável                                                                   | SPEC 2.4. O mínimo de 600.000 é imposto também na importação: um arquivo com menos iterações é recusado.                                                                       |
| Dados autenticados (AAD) | O id do cofre entra como dado autenticado do AES-GCM                                                                                                                                                                             | Impede trocar o conteúdo cifrado de um cofre pelo de outro sem que isso seja detectado.                                                                                        |
| Conferência da senha     | Feita ao decifrar o conteúdo (a tag do GCM falha com senha errada)                                                                                                                                                               | Não é preciso guardar nenhum verificador de senha.                                                                                                                             |
| Armazenamento            | `idb` (IndexedDB), store `vaults`; um registro por cofre com metadados em claro + `payload` cifrado                                                                                                                              | Em fases futuras, imagens das páginas podem ir em registros cifrados separados para não regravar tudo a cada alteração.                                                        |
| Persistência             | `navigator.storage.persist()` ao criar ou importar um cofre                                                                                                                                                                      | Evita que o Android apague os dados quando falta espaço.                                                                                                                       |
| Nome do cofre            | Obrigatório, até 80 caracteres, único (sem diferenciar maiúsculas), aviso para não usar nomes de pessoas                                                                                                                         | A confirmação de exclusão exige digitar o nome, por isso ele precisa ser único.                                                                                                |
| Força da senha           | Estimador próprio (sem zxcvbn, que tem ~800 kB): tamanho, classes de caracteres, penalidade para palavras óbvias, sequências e repetições, e ~13 bits por palavra em frases. Exige ≥ 10 caracteres e nível "Razoável"            | Indicador simples, offline e sem dependências.                                                                                                                                 |
| Bloqueio por inatividade | Padrão 10 min (1 a 60 nas Configurações); conferido por horário, não só por timer                                                                                                                                                | Os navegadores congelam timers em abas ocultas; ao voltar, o tempo decorrido é conferido na hora.                                                                              |
| Bloqueio ao ocultar      | Padrão **imediato** (SPEC 2.5), com opções "após 1 min", "após 5 min" e "não bloquear ao sair". Fechar o app (`pagehide`) sempre bloqueia                                                                                        | No tablet, colar o texto no app da IA oculta o Anonimizador. Com o padrão imediato, é preciso digitar a senha de novo ao voltar; o usuário pode afrouxar isso conscientemente. |
| Preferências             | `localStorage`, em claro                                                                                                                                                                                                         | Só contém tempos de bloqueio, nada do inquérito.                                                                                                                               |
| `.ipcofre`               | JSON `{format: "anonimizador-ip/cofre", formatVersion: 1, id, name, datas, kdf, cipher.iv, payload}` em base64. A importação pede a senha e decifra antes de gravar                                                              | Erro claro já na importação, em vez de um cofre que não abre.                                                                                                                  |
| Conflito na importação   | Mesmo id → pergunta se deve substituir (mostra as datas das duas versões). Mesmo nome com outro id → importa como "Nome (importado)"                                                                                             | Evita sobrescrever um cofre sem querer.                                                                                                                                        |
| Apagar tudo              | Digitar `APAGAR TUDO`; apaga o IndexedDB e as preferências, mas mantém o cache do app                                                                                                                                            | O app continua funcionando offline depois.                                                                                                                                     |

## Fase 2 — Importação de PDF e extração de texto

| Tema                          | Decisão                                                                                                                                                                                                                                                                                                                                                                               | Motivo                                                                                                                                                        |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Onde roda o pdf.js            | Todo o pdf.js (análise **e** renderização) roda num Web Worker próprio (`src/pdf/pdf.worker.ts`), sem worker aninhado, com `OffscreenCanvas`, fábrica de filtros vazia e fontes desenhadas como contornos (`disableFontFace`)                                                                                                                                                         | SPEC 3: nada pesado na thread principal. A mesma base renderiza as páginas a 300 DPI para o OCR na Fase 3.                                                    |
| Recursos do pdf.js            | `cmaps`, `standard_fonts`, decodificadores WASM (JBIG2, JPEG 2000, cor) e perfis ICC empacotados em `pdfjs/` por um plugin do Vite e pré-cacheados (~4 MB)                                                                                                                                                                                                                            | SPEC 2.2. PDFs escaneados costumam usar JBIG2 ou JPEG 2000. O pdf.js 5 não usa `eval`.                                                                        |
| Ordem de leitura              | Itens agrupados por linha de base (tolerância de meia altura de fonte), ordenados da esquerda para a direita, espaço quando o vão passa de 15% da fonte; vão vertical grande vira linha em branco. Coordenadas no espaço do viewport (cobre páginas giradas)                                                                                                                          | No IP fictício, o texto extraído é idêntico ao gabarito, palavra por palavra, nas 15 páginas. Texto em colunas não é tratado.                                 |
| Classificação                 | "Com texto" se houver mais de 30 caracteres alfanuméricos; senão "imagem"                                                                                                                                                                                                                                                                                                             | Critério do SPEC.                                                                                                                                             |
| Folhas                        | Carimbo (`Fls. 12`, `Fl. 12`, `FLS.: 12`, `fls nº 12`) nos 18% superiores ou 10% inferiores da página, ou número isolado no canto superior direito. Citações no corpo ("às fls. 5 a 8") são ignoradas. Prioridade: correção manual > deslocamento informado > detectada > **estimada** pela página detectada mais próxima. Sugere o deslocamento quando ≥ 60% das detecções concordam | Páginas escaneadas ficam sem detecção até o OCR, mas recebem uma folha estimada pelas vizinhas. Folhas são números inteiros (versos "12-v" não são tratados). |
| Armazenamento                 | Novo store `blobs` (IndexedDB v2): PDF original e miniaturas, cada um cifrado com IV próprio e AAD `cofre + id do blob`. O texto das páginas fica no conteúdo cifrado principal. Conteúdo e blobs são gravados na mesma transação                                                                                                                                                     | O PDF original é necessário para o OCR. Miniaturas são decifradas sob demanda, só quando aparecem na tela.                                                    |
| `.ipcofre`                    | Passa a incluir os blobs (ainda `formatVersion: 1`; o campo é opcional)                                                                                                                                                                                                                                                                                                               | Levar o inquérito inteiro para outro aparelho.                                                                                                                |
| Duplicados                    | PDF com o mesmo SHA-256 já presente no cofre é recusado                                                                                                                                                                                                                                                                                                                               | Evita páginas e entidades duplicadas.                                                                                                                         |
| Bloqueio durante a importação | A importação é cancelada se o cofre for bloqueado ou se o usuário sair da tela Documentos. Nada é gravado pela metade                                                                                                                                                                                                                                                                 | Não deixar texto do IP em memória depois do bloqueio.                                                                                                         |
| CSP em workers                | A CSP por meta tag não se aplica a Web Workers (o GitHub Pages não permite cabeçalhos HTTP). O worker só usa recursos do próprio app, e o teste E2E de zero requisições externas cobre o worker                                                                                                                                                                                       | Limitação da plataforma, registrada aqui.                                                                                                                     |

## Fase 3 — OCR offline

| Tema                         | Decisão                                                                                                                                                                                                                                                                                                         | Motivo                                                                                                                                                                                               |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Arquitetura                  | Um Web Worker de OCR (`src/ocr/ocr.worker.ts`) abre o PDF com o pdf.js, renderiza a página a 300 DPI em `OffscreenCanvas`, pré-processa e chama o tesseract.js (que roda no próprio worker dele). A imagem da página nunca passa pela thread principal. Cancelar = encerrar o worker (libera a memória na hora) | SPEC 3: nada pesado na thread principal; uma página por vez, com a memória liberada a cada página.                                                                                                   |
| Motor e modelo               | tesseract.js 7, núcleo só-LSTM (variantes _relaxed SIMD_, SIMD e sem SIMD, escolhida em tempo de execução) e `por.traineddata` do **tessdata best_int** (1,4 MB compactado)                                                                                                                                     | O best_int dá a melhor precisão por tamanho. O pré-cache do app passa a ~14 MB. Cache próprio do tesseract.js desligado (`cacheMethod: 'none'`): o service worker já guarda os arquivos.             |
| Pré-processamento            | Escala de cinza e esticamento de contraste (corta 0,5% dos extremos), sempre. Binarização de Otsu opcional, em Configurações (desligada por padrão)                                                                                                                                                             | Em páginas limpas, a binarização piora o resultado. Em cópias manchadas, ajuda.                                                                                                                      |
| Texto e confiança            | Texto montado a partir de blocos, parágrafos, linhas e palavras do Tesseract. Palavras com confiança abaixo de 70 são guardadas como trechos `[início, fim)` e destacadas em amarelo. A confiança média da página é ponderada pelo tamanho das palavras                                                         | Os destaques são apagados quando o usuário corrige o texto (as posições deixam de valer).                                                                                                            |
| Folha nas páginas escaneadas | Primeiro, procura o carimbo nas linhas reconhecidas. Se não achar, faz uma segunda leitura só do canto superior direito (9% superiores, 45% à direita), **apagando linhas longas** (bordas de carimbo, com tolerância a inclinação) e tentando os modos "bloco" e "texto esparso"                               | O Tesseract descarta texto emoldurado ao segmentar a página inteira. Com a segunda leitura, as 15 folhas do IP fictício escaneado são detectadas. Números de folha manuscritos não são reconhecidos. |
| Execução                     | O OCR fica num estado global (`ocrStore`): continua ao navegar (por exemplo, para conferir as páginas já prontas). Cada página reconhecida é gravada cifrada na hora. Bloquear o cofre interrompe o OCR, e as páginas concluídas são preservadas                                                                | Nada se perde se o tablet bloquear no meio.                                                                                                                                                          |
| Bloqueio por inatividade     | Cada página concluída conta como atividade do usuário (evento interno)                                                                                                                                                                                                                                          | Um OCR longo, iniciado pelo usuário, não deve ser interrompido por "inatividade". O bloqueio ao ocultar o app continua valendo.                                                                      |
| Tela de conferência          | Rota `#/conferencia/:doc/:página`: imagem renderizada a 150 DPI no worker do pdf.js (o PDF decifrado só é enviado ao worker quando muda o documento), zoom de 50% a 300%, texto com destaques, edição e navegação anterior/próxima. Lado a lado em paisagem, empilhado em retrato                               | SPEC Fase 3.                                                                                                                                                                                         |
| PDF pesquisável              | Opção em Configurações (desligada por padrão). Ao fim do OCR, monta com `pdf-lib`, carregado sob demanda, um PDF com as páginas reconhecidas (imagem + camada de texto do Tesseract) e as demais copiadas do original. O arquivo é oferecido para baixar e não fica no cofre                                    | O arquivo baixado não é cifrado: o app avisa.                                                                                                                                                        |
| Medição                      | `npm run bench:ocr` roda o OCR nas 15 páginas escaneadas do IP fictício, no app de produção e sem internet, e compara com o gabarito                                                                                                                                                                            | Ver resultados abaixo.                                                                                                                                                                               |

### Resultados do OCR no IP fictício escaneado (15 páginas, 200 DPI, com rotação e ruído)

Medido neste ambiente (Chromium headless, Intel Xeon 2,8 GHz, 1 núcleo por worker):

- **Tempo médio: 3,4 s por página** (renderização + pré-processamento + OCR + leitura do carimbo); 51 s no total.
- **Taxa de erro de caracteres (CER): 0,52%.**
- **Folhas detectadas: 15/15.**
- Ocorrências encontradas exatamente no texto: nomes de pessoas 98% (57/58; 1 perda por um "." inserido no meio do nome), CPF, RG, CNH, telefone, placa, CEP, datas, BO, IP e número CNJ **100%**, endereço 89%, chassi/Renavam 75% (`O`↔`0`), e-mail e chave Pix 0% (`@` lido como `Q`; a chave Pix quebrada entre linhas). A Fase 4 precisa tolerar essas trocas típicas.

**Estimativa para o Mi Pad 5 (Snapdragon 860):** a emulação de CPU lenta do Chrome não afeta Web Workers, então não dá para simular o tablet aqui. Pela diferença de desempenho por núcleo (Cortex-A76 a 2,96 GHz frente a um Xeon de servidor, cerca de 1,7 a 2,5 vezes mais lento em WebAssembly), a estimativa é de **6 a 9 s por página**, ou seja, 1,5 a 2,5 min para 15 páginas. O app mostra o tempo médio real ao fim de cada OCR, para conferir no aparelho. Se for lento demais, uma melhoria possível é processar 2 páginas em paralelo (o tablet tem 8 núcleos e 6 GB de RAM), o que contraria o "uma página por vez" do SPEC e por isso não foi feito.
